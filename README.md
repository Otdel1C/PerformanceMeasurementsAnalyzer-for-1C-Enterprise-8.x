# Отчет для просмотра и анализа замеров производительности в конфигурациях на базе БСП

Отчет доступен для использования в конфигурациях, имеющих в своем составе подсистему "Оценка производительности" из "Библиотеки стандартных подсистем"

## Статус и назначение

Это прототип внешнего отчёта. Работоспособность во всех версиях ERP, БСП и платформы 1С не подтверждена.

Отчёт **анализирует уже накопленные замеры**, но не включает их сбор. Основной источник —
`РегистрСведений.ЗамерыВремени`. Если конфигурация содержит
`РегистрСведений.ЗамерыВремениТехнологические`, код отчёта пытается подключить
и этот источник. Наличие подсистемы «Оценка производительности» в БСП обязательно.

## Быстрый запуск

1. Убедитесь, что в информационной базе включена и настроена подсистема
   **«Оценка производительности»**, а в выбранном периоде есть замеры ключевых операций.
2. Получите [готовый файл отчёта](./АнализЗамеровПроизводительности.erf).
3. Администратор один раз регистрирует его как **дополнительный отчёт** через
   «НСИ и администрирование → Печатные формы, отчёты и обработки →
   Дополнительные отчёты и обработки» (название и размещение раздела
   зависят от конфигурации и прав).
4. Настройте доступ к дополнительному отчёту для пользователей, которым нужен анализ.
5. Откройте **«Анализ замеров производительности»**, выберите вариант
   и период, затем нажмите **«Сформировать»**. В поставляемых настройках
   СКД вариантов установлен период **«Текущая неделя»**.
   При наличии соответствующей команды в форме можно включить «Формировать сразу».

> **Безопасность.** Сейчас `СведенияОВнешнейОбработке()` возвращает
> `БезопасныйРежим = Ложь`. Не подключайте непроверенный файл в рабочей базе;
> предварительно испытайте отчёт на тестовой базе и согласуйте запуск
> с администратором.

## Какой вариант выбрать

| Задача | Вариант отчёта |
| --- | --- |
| Оценить ключевые операции по APDEX и средней длительности | Анализ производительности (APDEX) |
| Найти изменения длительности в течение дня | Динамика длительности операций (по часам) |
| Посмотреть тенденцию за несколько дней | Динамика длительности операций (по дням) |
| Сравнить длительность операций у разных пользователей по часам | Динамика длительности операций пользователей (по часам) |

В СКД доступны отборы, в том числе по ключевой операции и пользователю.
Расширенный выбор пользователей подготовлен в [черновом PR № 1](https://github.com/Otdel1C/PerformanceMeasurementsAnalyzer-for-1C-Enterprise-8.x/pull/1),
но не входит в `master`.

## Если отчёт не показывает нужных результатов

| Симптом | Что проверить |
| --- | --- |
| Пустой результат | Период и факт наличия записей в `РегистрСведений.ЗамерыВремени` за этот период. |
| Нет нужной операции | Настройку регистрации соответствующей ключевой операции в подсистеме БСП. |
| Нет доступа к отчёту | Подключение дополнительного отчёта, его размещение и права пользователя. |
| Не выполняется запрос / отсутствует источник | Наличие подсистемы и регистра `ЗамерыВремени` в текущей конфигурации; версию БСП и текст ошибки. |
| Отчёт формируется долго | Уменьшить период, выбрать конкретную ключевую операцию и проверить объём замеров. |

APDEX здесь вычисляется выражением СКД с дополнительными коэффициентами
приоритета и количества операций. Перед использованием как контрольного
показателя проверьте формулу на известных примерах; она не должна автоматически
считаться стандартной реализацией APDEX.

## Проверка перед использованием в рабочей базе

1. На тестовой базе с существующими замерами сформируйте каждый из четырёх
   вариантов отчёта за небольшой период.
2. Выберите период без замеров и проверьте поведение отчёта.
3. Проверьте работу под пользователем с обычными (не административными) правами.
4. Если есть регистр `ЗамерыВремениТехнологические`, отдельно проверьте отчёт
   с ним и на базе без этого регистра.
5. Убедитесь, что выбранные настройки сохраняются и отчёт повторно открывается.

## Разработка и выпуск

- Исходники находятся в каталоге [`src/`](./src/), готовый внешний отчёт —
  в файле [`АнализЗамеровПроизводительности.erf`](./АнализЗамеровПроизводительности.erf).
- Версия, указанная в модуле регистрации отчёта ветки `master`, — `1.0`.
- Изменение файлов `src/` **не обновляет** `.erf` автоматически. В репозитории
  не обнаружена подтверждённая процедура сборки и проверки файла `.erf`;
  новая версия должна быть собрана и испытана в 1С отдельно.
- Наличие файла `.erf` и исходников не является подтверждением успешной
  проверки отчёта в рабочей базе.
