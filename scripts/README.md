# Сборка упрощённого запуска APDEX

## Почему необходима отдельная сборка

Исходный `АнализЗамеровПроизводительности.erf` **не содержит пользовательской формы**. Файлы
`src/ФормаОтчета/Ext/Form.xml` и `src/ФормаОтчета/Ext/Form/Module.bsl`
первоначально являлись отдельными исходниками и не были зарегистрированы в метаданных
`.erf`. Прямое изменение этих файлов без включения формы в отчёт не даёт работающего интерфейса.

Скрипт `scripts/build-quick-launch.ps1` создаёт **отдельную сборку** посредством
Конфигуратора 1С: сначала выгружает оригинальный `.erf` в стандартный XML,
затем регистрирует форму `ФормаОтчета`, исправляет тип основного реквизита
(`ExternalReportObject`) и загружает XML обратно в новый `.erf`.
**Существующую СКД и модуль объекта он не переписывает.**

> Это сценарий сборки, а не свидетельство, что отчёт компилируется или работает.
> Прогон в Конфигураторе и ERP ещё не выполнен. PR № 5 остаётся черновиком.

## Требования

- Windows PowerShell 5.1 или новее (установлен по умолчанию во многих версиях Windows).
- Локально доступный Конфигуратор соответствующей версии платформы 1С:Предприятие 8.3.
- **Тестовая** информационная база, доступная пользователю, выполняющему сборку.
- Копия текущей ветки `feature/quick-launch-skd-bsp`. Права администратора Windows не требуются, если доступ к тестовой базе и Конфигуратору уже есть.

### Для файловой тестовой базы

Открыть PowerShell в корне репозитория:

```powershell
.\scripts\build-quick-launch.ps1 `
  -DesignerExe "C:\Program Files\1cv8\8.3.27.2074\bin\1cv8.exe" `
  -InfoBase "C:\Bases\TestERP" `
  -KeepWork
```

Указанный путь к платформе — **пример**, используйте реально установленную версию.

### Для серверной тестовой базы

```powershell
.\scripts\build-quick-launch.ps1 `
  -DesignerExe "C:\Program Files\1cv8\8.3.27.2074\bin\1cv8.exe" `
  -ConnectionMode S -InfoBase "test-server\TestERP" `
  -KeepWork
```

Не передавайте пароли через параметры скрипта и не указывайте рабочую информационную базу.

## Результат

При успешном выполнении скрипт выводит:

- путь к **новому** `dist/АнализЗамеровПроизводительности.БыстрыйЗапуск.erf`;
- SHA-256 исходного и собранного файлов;
- ссылку на временный рабочий каталог с выгрузкой, а также журналами выполнения (при `-KeepWork`).

Оригинальный `АнализЗамеровПроизводительности.erf` остаётся неизменным.

Если выходной файл уже существует, сборка не перезаписывает его без явного `-Overwrite`.

## Проверка

1. Проверить журнал сборки и факт появления файла `.erf`.
2. Открыть новый файл через Конфигуратор тестовой базы и проверить синтаксис модулей.
3. Запустить его в 1С под обычным пользователем. Проверить: текущая неделя, APDEX, все пользователи; одно формирование по кнопке.
4. Изменить период, сформировать повторно и сравнить показатели с обычным отчётом при равных настройках.
5. Открыть «Подробные настройки», проверить работу стандартных средств БСП и отсутствие изменений сохранённых вариантов.
6. Проверить работу в базе с отсутствующими замерами и при доступе обычного пользователя.
7. Сверить результаты с 11 сценариями в [verification.md](../verification.md).

**Риск архитектуры:** внедрение копии типовой формы БСП увеличивает зависимость от
её версии. Доработку нельзя сливать в `master` без оценки совместимости и
проверки, что штатная форма настроек БСП доступна в конкретной ERP.

**Статус:** до выполнения шагов 1–7 функциональность не подтверждена.
